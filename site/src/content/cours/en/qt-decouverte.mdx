## Introduction

A new theme on this site: **development**, entering through **graphical interfaces**. This course takes up and modernizes Vincent Barichard's Qt course (LERIA, University of Angers): the substance is his, the target is **Qt 6** — and, true to this site's habits, every example shown is a real file, **compiled and executed by CI**. This module's goals:

- know what Qt is, where it comes from, under which licences it lives;
- measure what it covers (much more than the GUI);
- build and run your first program, with CMake.

## What is Qt?

**Qt** (pronounced *cute*) is a C++ **framework**: a set of libraries *and* a way to structure your application — fully object-oriented, whose historical QtWidgets module builds **native** graphical interfaces (the application looks like it belongs on its host system). Development started in 1994 at Trolltech; it is carried today by **The Qt Company** and a community (the *Qt Project*), after a stint at Nokia (2008-2012) then Digia — the eventful history never interrupted development.

**Portability** is the founding argument: the same code recompiles for Linux/X11/Wayland, Windows, macOS, Android, iOS and embedded targets. KDE (the desktop environment), VLC, OBS Studio and plenty of in-vehicle software are written with Qt. *Bindings* exist for other languages — Python first (PySide, the official binding).

<Note type="info" title="Licences: read before you undertake">
  Qt ships under **free licences** (LGPL v3 for most modules, GPL for some) and under a **commercial licence**. For a lab, free software or internal use, the LGPL covers everything; it is when distributing a *statically linked* proprietary product that the question turns serious. A professional reflex you know by now: the licence is read **before** the first line of code.
</Note>

## What Qt can do

The GUI is the tree hiding the forest. Qt also provides: **containers and strings** (QString is natively Unicode), files and streams, **networking** (HTTP, TCP/UDP, WebSockets), **databases** (PostgreSQL, SQLite, MySQL…), XML and JSON, threads, 3D, full **internationalization** (Qt Linguist) — all portable. A Qt application may have no window at all: half of this course's examples are console programs.

Two mechanisms set Qt apart in the C++ landscape:

- the **meta-object system** (and its compiler **moc**): it gives Qt objects introspection, properties and **signals and slots** — the communication mechanism replacing *callbacks*, the heart of [module 2](../qt-objets-signaux/);
- complete **tooling**: Designer (draw interfaces), Linguist (translate), and the **CMake** integration — [module 4](../qt-outils/) reviews them.

    `cmake -S . -B build` **configures**: it reads `CMakeLists.txt`, finds Qt (`find_package(Qt6…)`) and generates the build files into `build/` (the source directory stays clean). `cmake --build build` **compiles**. <Note type="warning" title="qmake, .pro: the old world">
  The original course (Qt 4 era) built with **qmake** and its `.pro` files (`SOURCES = hello.cpp`, `CONFIG += qt warn_on release`…). qmake still exists, and you will meet `.pro` files in many projects — but since Qt 6, **CMake is the official tool**: it is what the documentation, the IDEs and this course use. Another period piece: `#include <Qt/QtGui>` then "the include that includes everything" — today one includes **one class = one header** (`#include <QLabel>`), and widgets live in the **QtWidgets** module (split from QtGui since Qt 5).
</Note>

## Recap

- **Qt**: an object-oriented, portable C++ framework (desktop, mobile, embedded), LGPL/GPL/commercial licences — to read before undertaking.
- Much more than GUI: containers, networking, SQL, i18n… — and two singularities: the **meta-object system** (signals/slots, moc) and the tooling.
- The skeleton: one **QApplication**, widgets (the top-level **on the stack**), and `app.exec()` — the event loop.
- **CMake** is Qt 6's build system (qmake/`.pro`: the old world, still visible in the wild).
- The course's examples are compiled **and executed** by CI (`--smoke`), and the screenshots regenerated from the code (`--capture`).
