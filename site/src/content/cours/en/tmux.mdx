## Introduction

The [SSH module](../ssh/) stated the problem: an SSH session dies with the connection, taking whatever ran in it. It also named the solution — **tmux** — in four commands. This module gives it the room it deserves: it is the tool you will open *first* on every server, for your whole administration life. Goals:

- understand the model (server, sessions, windows, panes — and the prefix);
- survive a disconnection, recover your work, work across several terminals;
- navigate history (copy mode) and share a session between two people;
- configure tmux, then **declare** your environment with tmuxp.

## The model: one server, sessions, a prefix

tmux's trick fits in one sentence: when you launch `tmux`, a **server** starts in the background, and your terminal becomes a mere **client** displaying it. Close the terminal, cut the connection: the server — and everything running inside — carries on. That server hosts **sessions** (one per working context), each session holds **windows** (tabs), each window one or more **panes** (side-by-side sub-terminals).

All keyboard commands go through the **prefix** — `Ctrl+b` by default: press `Ctrl+b`, release, then the command key. Below, `prefix c` means "Ctrl+b, then c".

## Surviving: the detach / reattach cycle

```console
ada@serveur ~ $ tmux new -s admin        # create the "admin" session
# … work … then: prefix d                # detach (everything continues)
ada@serveur ~ $ tmux ls
admin: 2 windows (created Mon Jul  6 10:12:03 2026)
ada@serveur ~ $ tmux attach -t admin     # find everything again — even after a drop
```

The decisive point: **a brutal disconnection is equivalent to a detach**. Network cable yanked, Wi-Fi lost, terminal closed by mistake — the session still lives on the server, `tmux attach` brings it back, the compilation noticed nothing. It is the life insurance of any long operation (upgrade, migration, backup) launched over SSH — the SSH module's exercise had you live it, this one equips it.

<Note type="warning" title="The professional reflex">
  On a server, the **first** command after `ssh` is `tmux new -s …` (or `tmux attach`). Not the second: the first — *before* launching anything long. The day you think of it afterwards, it is too late: an already-running process cannot be cleanly repatriated into tmux.
</Note>

## Windows and panes: the workstation

The daily commands, in adoption order:

- **windows**: `prefix c` (create), `prefix n`/`p` (next/previous), `prefix 1`…`9` (go to), `prefix ,` (rename — do it, the status bar becomes a map);
- **panes**: `prefix %` (vertical split), `prefix "` (horizontal), `prefix arrows` (navigate), `prefix z` (**zoom**: the pane alone, full screen; `z` again to return), `prefix x` (close);
- **rescue**: `prefix ?` lists every binding; `prefix :` opens tmux's command prompt (every binding has its long command).

The classic working pattern on a server: one pane for editing, one for tests, a narrow pane for the logs (`journalctl -f`) — one single SSH connection carries it all.


    `htop` is still running, exactly where you left it: the panes' programs belong to the tmux **server**, not to the terminal that displayed it. That is the whole model — and why a server's `surveillance` window can stay open for months.

## Copy mode: going back in time

The mouse wheel stops being enough once the terminal is multiplexed: tmux keeps its own history per pane. `prefix [` enters **copy mode**: scroll up (arrows or `PgUp`), **search** (`Ctrl+s`/`Ctrl+r` in the default Emacs mode; `/` and `?` in vi mode), select and copy, `q` to leave, `prefix ]` to paste. With the configuration below, copy mode speaks **vi** — the [Vim module](../vim/)'s reflexes serve again, down into the terminal.

## Sharing: two people, one session

Two people connected to the same account can attach to the **same session**: each sees what the other types, live. It is the tool of four-hand debugging, handovers and tutoring — the person learning drives, the person accompanying sees everything, over any SSH link (`tmux attach -t admin -r` to attach **read-only**: watch without risking a touch).

## Recap

- tmux = a **server** your terminals merely display: disconnection = detach, never a loss — `tmux new -s`, `prefix d`, `tmux ls`, `tmux attach -t`.
- **Sessions** (contexts) > **windows** (tabs — rename them) > **panes** (`%`, `"`, zoom `z`); `prefix ?` to the rescue.
- **Copy mode** (`prefix [`): per-pane history, navigable and searchable — with vi keys using the course's configuration.
- **Sharing**: several clients on one session (`-r` for read-only) — debugging and tutoring.
- `~/.tmux.conf` aligns the tool with your reflexes; **tmuxp** declares the environment in YAML — the desired state in a file, as always.
- First reflex on a server: `tmux` first, work second.
